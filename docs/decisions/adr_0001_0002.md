# QRSIP — ADRs
#
# ADR-0001 — Python packaging and dependency management
# =========================================================
#
# Status: ACCEPTED
#
# Context:
# P02 is a Python-first research platform. We need a packaging approach that
# supports editable local development, reproducible dependency installation,
# CI mirroring local verification, and future distribution or containerization.
#
# Decision:
# Use a single `pyproject.toml` at repository root with setuptools backend.
# The package lives under `src/qrsip/`. Development dependencies live in
# `[project.optional-dependencies] dev`. Frozen requirements are generated by
# `make bootstrap` into `requirements-frozen.txt` and used by security checks.
#
# Alternatives considered:
# - Poetry: heavier tooling; not required by current scope.
# - pip-tools: possible, but `requirements-frozen.txt` generation is enough
#   for current reproducibility and audit needs.
# - Multiple packages: deferred; single package keeps the early architecture
#   simpler.
#
# Consequences:
# - Reproducible installs via pinned dev dependencies.
# - CI can audit frozen requirements.
# - Adding a second package later would require an ADR.
#
#
# ADR-0002 — Storage port first, PostgreSQL introduced when required
# ===================================================================
#
# Status: ACCEPTED
#
# Context:
# The architecture mentions PostgreSQL for registry/lineage. However,
# introducing PostgreSQL from day one adds operational complexity without a
# concrete current requirement.
#
# Decision:
# Start with a storage port abstraction and file/portable-backed storage for
# early phases. Introduce PostgreSQL only when registry/lineage capability
# requires it, and at that point implement migrations, schema, repository
# layer, tests, and failure handling.
#
# Alternatives considered:
# - PostgreSQL from day one: adds operational burden before it is needed.
# - Pure file storage forever: acceptable early, but may become limiting for
#   queryable lineage at scale.
#
# Consequences:
# - Domain logic remains independent of PostgreSQL.
# - We can delay the database migration/operational burden until justified.
# - Future introduction must follow migration + adapter + test discipline.
